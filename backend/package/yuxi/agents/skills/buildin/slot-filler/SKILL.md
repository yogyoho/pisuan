# 智能填槽

在段落模板推荐（template-recommender）完成后，根据对话上下文、用户上传的附件文件以及知识库中的可用数据，智能填充模板中的每个插槽。所有填充数据必须可溯源，不允许编造任何事实性数据。

## 前置条件

此技能依赖 `template-recommender` 技能。上文中必须已有模板推荐结果（包含章节模板和插槽定义）才能执行填槽。若尚未执行模板推荐，应先触发 `template-recommender` 技能。

## 操作流程

### 第一步：解析模板输入

1. 从上文对话中提取 `template-recommender` 输出的模板列表
2. 确认每个模板的以下信息：
   - `template_id`：模板唯一标识
   - `section_path` / `section_title`：所属章节
   - `slots`：插槽定义数组（每个 slot 包含 `name`、`type`、`description`）
   - `standard_code`：关联的标准编码

### 第二步：收集可用数据源

按优先级收集可用于填充的数据：

1. **用户上传的附件**：检查对话中用户是否提供了文件（如 `.docx`、`.xlsx`、`.pdf`、`.md`），使用 `read_file` 读取附件内容，提取其中的关键数据
2. **对话上下文**：从会话历史中提取用户已提供的项目信息、参数、约束条件等
3. **知识库原文**：使用 `read_file` 读取模板对应的知识库原文（路径：`/home/gem/kbs/<kb_name>/parsed/<filepath>.md`），从中提取原文中已有的具体数值和事实
4. **知识库搜索**：对于需要补充数据的 slot，使用 `query_kb` 在同领域 KB 中搜索相关数据

### 第三步：逐槽填充

对每个模板的每个 slot 执行填充：

1. **理解 slot 语义**：根据 `slot.name` 和 `slot.description` 理解该插槽需要什么类型的数据（如数值、文本描述、日期、单位等）
2. **匹配数据源**：在收集的数据源中搜索与该 slot 匹配的数据
3. **确定填充策略**：
   - **可填充**：数据明确存在 → 填入数据，标注置信度「高」和数据来源
   - **可推断**：可从多个数据源交叉印证 → 填入数据，标注置信度「中」和推断依据
   - **部分匹配**：数据存在但不完全匹配 → 填入最接近的数据，标注置信度「低」和不确定性说明
   - **无数据**：数据源中没有相关信息 → 标记为「待补充」，说明需要什么样的数据

### 第四步：输出填充结果

输出填充完成的模板，对无法填充的 slot 使用 `ask_user_question` 提示用户补充。

## 输出格式

```markdown
# 模板填充结果

## 填充摘要

| 指标 | 数量 |
|------|------|
| 插槽总数 | {N} |
| 已填充（高置信度） | {n} |
| 已填充（中置信度） | {n} |
| 已填充（低置信度） | {n} |
| 待补充 | {n} |

## 填充详情

### {章节路径} {章节标题}

**模板**: `{template_id}`

#### 已填充的插槽

| 插槽名 | 填充值 | 置信度 | 数据来源 |
|--------|--------|--------|----------|
| {name} | {value} | 高/中/低 | {来源说明} |

#### 待补充的插槽

| 插槽名 | 描述 | 需要的数据说明 |
|--------|------|----------------|
| {name} | {description} | {需要什么类型的数据、格式要求等} |

---
```

### 第五步：请求用户补充

对于所有标记为「待补充」的插槽，调用 `ask_user_question` 工具，整理成清晰的问题列表，引导用户逐一补充：

- 每个问题应说明：哪个章节的哪个插槽需要什么数据
- 提供数据格式示例或参考值
- 按章节分组，便于用户逐项填写

## 关键约束

- **绝对禁止编造数据**：不得凭空生成任何数值、名称、日期、参数。若数据源中不存在，必须标记为「待补充」而非猜测填充
- **置信度标准**：
  - 高：数据直接来自用户附件或原文，完全匹配
  - 中：数据可从多个来源交叉验证，有一定推断成分
  - 低：只有一个来源且匹配度不完整，或数据时效性不确定
- **数据溯源**：每个填充值必须标注数据来源（文件名、段落位置、或 KB 名称+chunk 引用）
- **数据不破坏**：填充的数值应保留原始精度和单位，不要四舍五入或换算（除非插槽明确要求特定单位）
- 填充时应保持上下文一致性——同一个项目名称、同一个参数在不同插槽中应填入相同的值
- 若用户随后补充了数据，应更新对应插槽的填充值和置信度
