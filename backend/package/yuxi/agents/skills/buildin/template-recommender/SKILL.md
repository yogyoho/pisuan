# 段落模板智能推荐

从用户对话设置中指定的领域知识库中，根据用户提问的关键字搜索匹配的章节和段落模板。若用户指定了具体章节（如"第四章 环境影响预测"），则递归搜索该章节及其所有子章节，将泛化模板与原文引用合并输出。

## 适用场景

- 用户需要编写某类工程报告的特定章节
- 用户提供了章节标题，需要获取该章节的标准模板结构
- 用户想了解某领域报告的章节组织方式和段落模板
- 报告智能编写流程的第一步——先获取模板，再填槽

## 操作流程

### 第一步：确认知识库范围

1. 调用 `list_kbs` 获取当前对话可用的知识库列表（这些 KB 由用户在对话设置中预先选定）
2. 若用户未指定知识库或可用 KB 为空，告知用户需先在对话设置中选择相关领域知识库

### 第二步：了解章节结构

1. 对每个相关 KB，调用 `get_mindmap(kb_name)` 获取该知识库的章节树结构
2. 从思维导图中理解报告的顶层章节组织、父子章节关系、章节编号体系
3. 若用户提到了具体章节编号或标题，在思维导图中定位该章节节点及其子树

### 第三步：搜索匹配模板

根据用户需求，分两种搜索策略：

**策略 A — 用户指定了具体章节（如"第四章 环境影响预测"、"4.1 大气环境"）：**
1. 使用章节标题作为 query_text，调用 `query_kb(kb_name, query_text)` 搜索该章节
2. 从搜索结果中提取该章节的 `section_id`，在思维导图中找到它
3. 遍历该章节的所有子章节（递归），对每个子章节也执行 `query_kb` 搜索
4. 确保该章节及其完整子树都被覆盖

**策略 B — 用户只给了关键字（如"大气环境影响"、"水资源"）：**
1. 将关键字组合成搜索短语，调用 `query_kb` 进行语义搜索
2. 从搜索结果中提取匹配的章节和段落
3. 根据 `section_path` 将结果按章节层级组织

### 第四步：读取原文并提取模板

1. 对搜索命中的每个 chunk，使用 `read_file` 读取知识库虚拟文件系统中的完整原文（路径格式：`/home/gem/kbs/<kb_name>/parsed/<filepath>.md`）
2. 从 chunk 的 metadata 中提取模板信息（`template_id`、`slots`、`generalized_pattern`）
3. 若 chunk 携带 `template` 元数据，优先使用；若没有，从原文中识别段落结构

### 第五步：合并输出

按以下 Markdown 格式汇总输出：

## 输出格式

```markdown
# 模板推荐结果

## 知识库概览
- 搜索范围：{KB名称列表}
- 搜索策略：{策略A 章节递归 / 策略B 关键字搜索}

## 章节结构概览

采用思维导图缩进格式，标注 **已匹配** 的章节：

- 第一章 总论
  - 1.1 项目背景 **[已匹配]**
  - 1.2 编制依据
- 第二章 工程分析 **[已匹配]**
  - 2.1 生产工艺 **[已匹配]**
  ...

## 模板详情

### {章节路径} {章节标题}

**标准编码**: `{standard_code}`
**匹配置信度**: {confidence}
**模板ID**: `{template_id}`

#### 泛化模板
{generalized_pattern}

#### 插槽清单
| 插槽名 | 类型 | 描述 | 必填 |
|--------|------|------|------|
| {slot.name} | {slot.type} | {slot.description} | {is_required} |

#### 原文引用
> {原始段落文本}

---
（对每个匹配的章节/段落重复以上结构）
```

## 关键约束

- 知识库范围限定在用户对话设置中已选定的知识库，不要跨库搜索
- 若指定了章节，必须递归包含其所有子章节，不可遗漏
- 原文引用必须完整保留原始措辞，不可修改或概括
- 若同一章节在多个 KB 中有匹配，分别列出并标注来源 KB
- 搜索结果为空时，明确告知用户未找到匹配模板，并建议调整关键字或确认知识库范围
- 不要编造模板或原文内容，所有输出必须来自知识库检索结果
