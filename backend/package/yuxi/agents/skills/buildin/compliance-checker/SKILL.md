# 合规性校验

对已完成或部分完成的报告内容进行政策法规合规性扫描。从知识库大纲中提取每个章节关联的法规标准，在 KB 中检索法规原文，逐章比对内容是否满足法规要求，输出结构化的合规校验报告。

## 适用场景

- 环评报告提交前的合规性自查
- 可行性研究报告的政策符合性审查
- 报告修改后的增量合规校验
- 特定章节的法规对标检查

## 前置条件

- 对话中已有待校验的报告内容（可以直接提供，或已写入文件）
- 已关联包含法规标准和报告大纲的领域知识库

## 操作流程

### 第一步：获取大纲与法规清单

1. 调用 `list_kbs` 确认可用知识库
2. 对每个章节调用 `get_chapter_outline(domain, report_type, canonical_chapter_key)`，取其 `regulations`（含 `standard_code`）与 `content_requirements`
3. 汇总生成法规清单（去重），标注每个法规关联的章节

### 第二步：检索法规原文

对清单中的每个法规/标准：

1. 以法规名称或标准编号（如 "GB 3095-2012"）为 query_text 调用 `query_kb`
2. 提取法规的关键条款：适用范围、限值要求、必填内容、格式要求
3. 若 KB 中未检索到该法规，标记为「法规原文未收录」并在校验报告中提示

### 第三步：逐章合规校验

对每个章节：

1. 读取该章节的报告内容（从对话上下文或文件）
2. 读取该章节关联的法规条款和大纲要求
3. 逐项比对：

| 校验维度 | 说明 |
|---------|------|
| **内容完整性** | 大纲要求的内容是否都已覆盖 |
| **标准引用正确性** | 引用的标准编号和名称是否准确 |
| **限值合规性** | 预测结果/设计参数是否满足标准限值 |
| **表述规范性** | 是否符合标准规定的表述格式（如单位、精度） |
| **必填项检查** | 法规要求的必填内容是否完整 |

4. 对每个校验项给出判定：
   - ✅ **合规**：内容满足法规要求
   - ⚠️ **待补充**：内容部分覆盖，缺少法规要求的某些方面
   - ❌ **不合规**：内容与法规要求冲突或严重缺失
   - ℹ️ **无法判定**：法规原文未收录，需人工核查

### 第四步：输出校验报告

```markdown
# 合规性校验报告

## 概览

| 状态 | 数量 |
|------|------|
| ✅ 合规 | {n} |
| ⚠️ 待补充 | {n} |
| ❌ 不合规 | {n} |
| ℹ️ 无法判定 | {n} |

## 逐章详情

### 第一章 总论

| 校验项 | 状态 | 说明 |
|--------|------|------|
| 评价标准引用 | ✅ | 已正确引用 GB 3095-2012 等 5 项标准 |
| 编制依据完整性 | ⚠️ | 缺少《建设项目环境影响报告表编制技术导则》 |
| 评价等级判定 | ❌ | 大气评价等级判定依据不足，未按 HJ 2.2-2018 要求计算等标排放量 |

...

## 建议修改项

1. **[第一章] 评价等级**：按 HJ 2.2-2018 第 5.3 节要求，补充最大地面浓度占标率 Pmax 计算过程
2. ...
```

## 关键约束

- 校验结论必须有依据：引用具体法规条款编号和原文内容
- 不编造法规内容：若 KB 中未收录某法规，如实标注「未收录」
- 校验是辅助工具，不替代法定审查程序
- 对于数值型合规判断（如浓度是否超标），需展示计算过程和比对依据
- 优先使用用户对话中关联的知识库进行法规检索，不跨库
