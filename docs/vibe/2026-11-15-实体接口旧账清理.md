# 实体接口旧账清理（2026-11-15）

依据：`docs/vibe/2026-11-14-领域实体构建器页面设计诊断.md` §4 P2-5 / P2-6 / §5.3.7。

## 目标

1. 同一概念不再存在三套互不相通的实体接口：保留 `/api/domain-entity-builder`（真实数据库），下线内存 STUB。
2. 删除全仓无消费者、且能绕过删除影响面的死接口（批量删除、默认种子）。
3. 清理后前端 API 层与后端路由一一对应，不再有「定义了但没人调用」的封装。

## 现状（问题）

| 死代码 | 证据 |
|---|---|
| `server/routers/entity_type_router.py`（211 行，内存 dict 存储，重启丢数据） | 注册在 `/api/entity-types`，除自身外全仓仅 `web/src/apis/entity_type_api.js` 引用；无页面调用、无测试 |
| `web/src/apis/entity_type_api.js` | 只有自身内部互相引用，无任何视图/组件导入 |
| `POST /entities/batch-delete` + `service.delete_entities_batch` + `repo.delete_many` + 前端 `batchDeleteEntities` | 前端从未调用；服务端批量删除不检查引用影响面（P1-3 已把单条删除改为先看影响面，这条路径会绕过它） |
| `service.seed_default_entities` | 无调用方；内部写死 `domain_code="coal"`，一旦被误用就会造出通用域读不到的幽灵实体（P1-5 同款问题） |

## 关键判断

- **删除而不是标注 deprecated。** 这两个文件都是 pisuan custom 自己引入的（`5395b0e9e`），不涉及上游同步；留着一个能读写的内存 STUB，迟早会被误当成真接口接上。
- **批量删除直接删，不接线。** 接线意味着要补「逐条影响面 + 强确认」的批量 UI，当前没有批量选择需求；先把这条能绕过守卫的路径关掉，等真要做批量操作时按 P1-3 的口径重新实现。
- **`coal_eia_entity_types.json` 保留。** 它仍被 `entity_meta_service`（变量元数据）与若干测试使用，本批只删挂在它上面的无调用方 seeder。

## 范围

**做**

- 删除 `entity_type_router.py` 及其在 `server/routers/__init__.py` 的注册。
- 删除 `web/src/apis/entity_type_api.js`。
- 删除 `/entities/batch-delete` 路由、`delete_entities_batch`、`repo.delete_many`、`batchDeleteEntities`。
- 删除 `seed_default_entities`。
- 同步 `docs/develop-guides/upstream-sync-guide.md` 的定制文件清单与 changelog。

**不做**

- 不动 `eia_entity_api`（EIA 样例实体补充，另有 `EntitiesPanel` 在使用）。
- 不做批量选择/批量删除 UI、不做软删除与恢复。
- 不改页面文案（P2-7 另列一批）。
