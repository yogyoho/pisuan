# 语料归纳实体体系（2026-11-16）

## 背景

插槽→实体绑定质量审计（bug-4288）显示 69.9% 绑定由 ≥2 字模糊匹配产生且系统性错绑，
根因之一是泛化 prompt 无实体词表、实体范围非语料锚定。用户提出：从现有 33 份环评报告
语料统一提取一套实体对象和属性，从源头确定实体范围。

## 用户决策（边界对齐）

1. **落库目标域**：本系统为特定行业客户定制（非 SaaS 多租户），每客户一个行业领域，
   不区分行业域、统称通用域（`GENERAL_DOMAIN_CODE`）。**直接增量补强通用域 52 实体**。
2. **对账原则**：`npp_model_parameters`（核电厂模型参数）可清理——已获用户批准 trash；
   其余"库有语料零现"实体待 Route A 对账报告出来后逐个裁定。
3. **语料来源**：coal-eia-writer 技能 `references/samples_bank/`（33 份报告 512 章节切片
   35.4MB）+ `references/stages/`（规划环评 33 表单族 139 字段 / 验收 25 族 12 字段，
   字段形态与实体属性同构）。原始 Word 暂不需要，切片覆盖出现缺口时再向用户索取。

## 路线

- **Route A（自上而下，零 LLM 成本）**：stages 字段清单 → 属性候选映射 → 与 52 实体对账
  → 产出：覆盖清单 + 缺口清单 + 零锚定实体清单。
- **Route B（自下而上，LLM 普查）**：512 切片按小节结构化抽取（实体候选/属性/证据/值形态）
  → 跨报告聚合 → 对账。表格段落优先，分批断点续跑，依赖 Route A 的缺口清单定批次范围。
- **产出去向**：Route A+B 词表 → 泛化 prompt 注入（配合 bug-4288 保障方案的匹配收紧、
  回流闸口），插槽名对齐属性名后 L1 绑定率从 10.4% 大幅提升。

## 验收标准
