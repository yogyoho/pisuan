# 方向 A：章节范式库（Section Paradigm Library）设计草案

日期：2026-10-07　|　状态：草案（待评审）　|　上游讨论：环评样例报告知识加工方向 brainstorm
前置：bug-367 三层修复（c6092c26）——契约正文人格条款、残留门扩词表、存量剥壳

## 1. 背景与定位

test2 全量跑暴露的行文人格失守（825 处元话语）已做三层修复：契约禁令（负向）、残留门（执法）、存量剥壳（补账）。但写作质量的缺口仍在：**写手只有「不准怎样」（禁令）和「写哪些内容」（要素链），没有「合格的段落读起来什么样」（正样本）**。行为科学的基本结论是：只给禁令不给示范，模型会以训练分布的平均水准填空——恰好是「AI 说明文」腔。

样例报告（横城矿区规划环评）的价值由此确定：**它不是检索语料，而是行文范式的蒸馏原料**。方向 A = 把样例报告蒸馏成结构化范式库，在派发契约中确定性注入。

## 2. 现状盘点（设计落点的关键事实）

技能 references 层已有三类资产，范式库必须与其咬合而非另起体系：

| 资产 | 现状 | 缺口 |
|---|---|---|
| `stages/*.json` 的 `sample_anchor`（13/13 章） | 横城样例**结构同构**描述：节号+节题清单+已知缺陷警告 | 只有骨架，无行文 |
| `stages/*.json` 的 `writing_patterns`（13/13 章） | 纪律条目（「预测数值全槽位」「禁引入横城实体」） | 是规则不是示范 |
| `chapter_examples/`（4 篇） | 沉陷/生态/水/大气**去实体化方法论模板**（占位符+`[待补充]`） | 面向人的说明文腔，非报告行文；仅覆盖 4 主题 |
| `sample_entities.md` + `_index.json` | 横城实体黑名单，泄露检测已在契约与门两处 | — |
| `.wolf/hj130_extract.md`、`hj463_extract.md` | HJ 130 规划环评导则 / HJ 463 固废导则提取物 | 可作结构佐证，非行文素材 |
| **语料池**（`.wolf/corpus-census/census.json`） | **41 份真实报批级环评报告 docx，约 600 万字符**：矿区规划环评 ~17 份、矿井/选煤厂项目环评 9 份、后评价 2 份、其他（复垦方案/露天矿等）13 份；W2 已建章题归一化 aliases（44 条）与三层条件化模板 | 范式蒸馏的**主素材源**，尚未被技能消费 |
| `sample_entities/`（25 个文件） | **24 份语料的实体黑名单**（项目/矿名/机构/地名/敏感目标分类），`_index.json` 聚合 | 泄露检测门已按多语料就位 |

**结论：独缺「去实体化段落级行文范文」这一层。** 元话语重灾区恰是 `sample_anchor` 覆盖最弱的节型——衔接/收束节（「与后续章节的衔接」「本章收束」类），其契约含上游/下游导航字段，写手无示范可依时直接转录字段。

## 3. 目标与非目标

**目标**
- G1 每节写手在派发契约中拿到与其节角色匹配的行文范式：结构骨架 + 2-3 段去实体化范文 + 句式模式 + 反模式对照。
- G2 重派稳定：范式为静态入库资产，同契约重派注入内容逐字节相同（重派=原 prompt 原文原则不破）。
- G3 实体零泄漏：范文全部去实体化，与 sample_entities 泄露检测门形成闭环。
- G4 test2 报告验证：以范式契约重派单节，残留门 0、实体门 0、人工盲评「像环评报告」。

**非目标**
- 不做运行时 RAG 主通道（LightRAG 语义召回无法保证范式类型精确、有实体污染、破坏重派确定性——RAG 只作辅助通道，见 §9）。
- 不改知识工厂现有功能（硬约束）。
- 不动门体系（残留门/深度门/一致性合约保持机械执法；范式是导航不是门）。
- 不做范文检索/向量库基础设施——范式文件是 git 内静态资产。

## 4. 设计总览

```
                     ┌─ 结构骨架 ← 已有 sample_anchor（不重复建设）
派发契约（4.1） ────┼─ 纪律条目 ← 已有 writing_patterns + 正文人格三禁（不重复）
                     ├─ 行文范式 ← ★ 本设计新增 references/paradigms/<role>.md
                     └─ 要素链/表族 ← 已有 elements/uses
                                          │
                     残留门/实体门/深度门 ← 机械执法（不变）
```

双通道：
- **主通道（本设计 P0）**：范式文件按节角色确定性注入契约——零召回风险、零实体风险、重派稳定。
- **辅通道（P1）**：去实体化样例段落入库现有知识库，写手 `query_kb` 按需扩写参考——召回错误只降参考质量，不伤结构。

## 5. 节角色类型学

范式按**节角色**组织（跨章复用），不按章组织。77 节一次性分配角色，分配结果落 stage 文件。

| 角色 | 定义 | 典型节 | 元话语密度 | V1 |
|---|---|---|---|---|
| `opener` | 章首定位节：对象+依据+范围+工作程序 | 1.1、2.1、12.1 | 中 | ✅ |
| `baseline` | 现状/概况描述节 | 3.x、4.x 回顾 | 低 | ✅ |
| `analysis` | 影响预测与评价主体节 | 6.2-6.10、7.x、8.x | 低 | ✅ |
| `measures` | 措施节（条目化：对象+内容+主体+时段） | 9.x、10.1 | 低 | ✅ |
| `linkage` | 衔接/收束节：与后续章节衔接、本章小结投影 | 1.3.5、6.10.9、8.7.7…（~15 节） | **高** | ✅ |
| `tabular` | 清单/资料表节（表格为主、行文为纲） | 1.4 依据清单、5.x 指标 | 中 | P2 |
| `conclusion` | 结论汇总节（逐要素一句一结论+来源指针） | 13.x | 低 | P2 |
| `process` | 程序/公众参与节 | 12.2/12.3 | 低 | P2 |

角色分配规则（一次性脚本+人工复核）：标题关键词（衔接|收束|小结|投影|对应关系→linkage）+ 章位（S01→opener 候选）+ 人工裁定。分配结果固化为独立映射文件 `references/paradigms/_roles.json`（stage 文件是上游同步敏感区，零改动）。

## 6. 范式文件

`references/paradigms/<role>.md`，Markdown（写手阅读自然，注入即贴文本）。V1 共 5 个文件。

结构（以 `linkage.md` 为例）：

````markdown
# 节角色范式：衔接与收束（linkage）

## 适用
章末小结、与后续章节衔接、结论投影类节。这类节的职能：以**内容**承接上文、
以**结论**指向下文——而不是以「本节的写法」自我说明。

## 结构骨架
1. 承接句：概括上文已确立的核心结论（指名内容，不用「其上游依据」式指称）
2. 实体段：本节实际内容的汇总陈述（与要素链一一对应）
3. 指向段：向后章节的口径衔接——句式见下

## 范文（按 stage family 分节；每 family 2-3 段**差异化**范文——多源蒸馏，非单一样例；去实体化，实体禁带入正文）
> 规划实施后，矿区地表沉陷影响范围约 [面积] km²，受影响村庄 [N] 个。
> 上述预测结果与生态环境影响评价结论互为印证，并构成减缓措施章中土地复垦
> 与村庄搬迁安置方案编制的基础。针对尚存在不确定性的 [要素]，下一阶段
> 项目环评中应进一步开展 [工作]。

## 句式模式
- 「上述……为第 X 章……提供了依据 / 构成了……的基础」（内容指称）
- 「与第 X 章……的结论一致 / 互为支撑」
- 「针对上述问题，第 X 章设置了……」
- 禁用句式见反模式

## 反模式（与残留门词表同源，新增词先进门表再同步此处）
| 禁止写法 | 为什么 | 改成 |
|---|---|---|
| 「其下游用途是为…」 | 契约导航字段转录 | 直接说「为第 9 章……提供了受影响对象清单」 |
| 「本节回答的是…」 | 节设计说明 | 直接开始回答 |
| 「就任务性质而言」 | 节设计说明 | 删除，直接陈述 |
````

要点：
- 范文按 family 分小节（planning / project / post-tracking），每 family 2-3 段、来自**不同语料源**——保留句式多样性，防止单源风格过拟合为「全报告风格」；注入契约时只贴对应 family 小节。
- 去实体化采用**泛化主体**（本矿区/规划区/[面积] km²）而非 `{{占位符}}`——写手参照的是句法与信息组织，泛化主体不会诱导占位符泄漏进正文。
- 反模式表与 `build_output.py` RESIDUE_RE **单一来源同步**：新禁词先进门表，再同步范式反模式（门是执法，范式是教学，两边同一词表）。
- 每文件 ≤ 120 行，注入契约的体积预算 ≤ ~800 tokens/节（骨架+范文+句式+反模式全量注入，不做截断裁剪——重派确定性要求注入内容只依赖角色，不依赖动态状态）。

## 7. 注入机制

三处小改动，无新代码路径（派发契约由编排代理按 SKILL.md 模板组装，注入即「自读输入」清单多一行）：

1. **角色映射文件** `references/paradigms/_roles.json`：`{"ch6_S02": "analysis", …}` 77 节一次性分配（§5 规则）；编排代理按节 id 查角色装载范式，查不到即报错拒派——显式优于静默回退。
2. **SKILL.md 4.1 契约模板**：自读输入清单增加一行
   `references/paradigms/<paradigm_role>.md（行文范式——范文仅示范句法与信息组织，其中实体与数值一律替换为本项目实体与冻结值）`
3. **契约正文**：正文人格条款追加一句「行文范式是正样本示范：结构与句法向它对齐；反模式表为硬禁令（违反=残留门 FAIL）」。

## 8. 范文蒸馏与实体红线闭环

**蒸馏素材**：语料池 41 份（§2），**非横城单源**——单一样例会把一种个人风格过拟合为「全报告风格」，且阶段覆盖不均。横城在池中仅是 planning 家族 17 份之一。

**蒸馏流程（一次性，人工评审后入库为静态资产）**：
1. **定位**：复用 W2 章题归一化 aliases 把 41 份 docx 的章题归一到 canonical，按「canonical 章 × 节角色」跨源定位候选段（docx 抽取沿用 census 普查脚本基础）。
2. **成色过滤**：文件名可辨成色——优先「报批版/出版/终稿/黑字版/会后修改稿」，弃征求意见稿与明显未完成稿。
3. **候选池**：每节角色从 N 份同类报告各抽 1-2 段（如 planning 的 linkage 节 ≈ 17 份 × 2 段），人工初筛弃说明文腔。
4. **归纳**：跨源共性结构 → 结构骨架（≥60% 源一致的模式才入骨架）；句式模式取跨源高频。
5. **差异化保留**：每 family 选 2-3 段**句式风格互异**的范文，去实体化（按对应源的黑名单替换为泛化主体/`[类别]`，数值改示意值）；来源文件名入范式文件脚注（溯源）。
6. 反模式直接采用 bug-367 五类元话语分类（实测 825 处 + 55 对替换对校准）。
7. 人工评审（逐文件）后入库。**范式文件不含任何语料池实体**——入库前对 `sample_entities/_index.json` 全部 24 份黑名单聚合扫描 0 命中为验收条件。

**闭环**：范文去实体化（源头）→ 契约声明「实体一律替换为本项目实体」（导航）→ sample_entities 泄漏门（执法）。三道防线各自独立。

## 9. RAG 辅通道（P1）

- 样例报告按段落切分 → 去实体化（同 §8 规则）→ 打节角色标签 → 经**现有知识库上传通道**入库（知识工厂零改动）。
- SKILL.md 4.1 既有「query_kb 检索同章叙述参考」表述细化为：检索结果仅作扩写参考，范式文件优先；检索到非本节角色段落时不参照。
- 排期后置：主通道验证通过后再做，避免辅通道噪音干扰主通道验收归因。

## 10. 验收标准

| # | 验收项 | 通过标准 |
|---|---|---|
| A1 | 范式库完整性 | 5 个角色文件 + 77 节角色分配 100% 覆盖；实体扫描对 `_index.json` 全部 24 份黑名单 0 命中 |
| A2 | 单节重派实验（test2） | 取元话语重灾区一节（如 ch6_S02 或 ch1_S02），以范式契约重派×2：残留门 0、实体门 0、两次产出结构一致、数字与表族引用正确 |
| A3 | 人工盲评 | 范式契约节 vs 基线节盲评「像不像环评报告」，范式版不劣于且段落级显著更自然 |
| A4 | 契约体积 | 单节契约增量 ≤ 800 tokens |
| A5 | 回归 | 重派=原 prompt 原文不被破坏（同节二次派发 prompt 逐字节相同）；既有门全 PASS |

## 11. 分期

- **P0（本设计核心）**：角色分配 + 5 个范式文件 + stage `paradigm_role` 字段 + SKILL.md 注入行 + A1-A5 验收。预计范式文件蒸馏与评审为主要工作量。
- **P1**：RAG 辅通道入库 + query_kb 纪律细化。
- **P2**：`tabular`/`conclusion`/`process` 三类补齐；与 depth_targets 地板校准（D1 积压）联动——范式骨架天然给出每节型合理段数，可反推地板。
