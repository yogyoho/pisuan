# 领域实体构建器 P0 重构实施（2026-11-14）

依据：`docs/vibe/2026-11-14-领域实体构建器页面设计诊断.md` §5.1 全部 7 项 + §8 P0/P1。

## 0. 目标

让「AI 提取 → 采纳 → 落库」这条链路**可用且不可污染 schema**：任何写库动作都有结构校验、证据校验与人工确认；同时修复已确认的页面失真（计数重复、样式失效、作用域缺失、值类型词表分叉）。

## 1. 范围与决策

| 决策 | 结论 |
|---|---|
| 实施位置 | 当前 `pisuan-localized` 工作树（运行栈挂载于此，热重载可测）；改动需在收尾时按 rename 规则回迁 `pisuan-custom` |
| 交付档位 | §5.1 全部 + §8 P0/P1；**不含** §5.2 组件拆分与 §5.3 设计升级 |
| 关系规则 | 接入 `graph_builder` 消费（不做"标注失效"的短期方案） |
| 值类型词表 | 以 builder 7 种（String/Integer/Float/Boolean/Enum/Object/List）为准；`Numeric→Float`、`Date→String` 作为显式兼容别名，其余未知值 400 |
| 键校验尺度 | 只校验契约必需项（非空、无空白与 `.`，≤64 字符）；snake_case 作为**新建键的生成规则**，历史 180 个中文 key 留到 §5.3.6 迁移，不阻塞保存 |

## 2. 契约变更（AI 提取 v2）

**核心原则：提取结果只用于生成/补全 schema 定义，实例值不落库。**

| 字段 | 含义 |
|---|---|
| `_status` | `matched`（已一致）/ `partial`（补属性）/ `new`（建实体提案） |
| `_entity_id` | matched/partial 指向的已有实体 |
| `_diff.add_properties` | 建议新增的属性定义（key/name_cn/value_type/sample_value） |
| `_proposed_entity` | new 状态的实体提案（含 `problems` 说明为何不可导入） |
| `grounded` | `extracted_text` 是否为原文子串（空白归一化后） |
| `confidence` | 模型自述置信度，仅作前端默认勾选依据；**不参与后端硬拒绝** |

硬拒绝只给两条客观规则：**无原文证据** 与 **new 提案的 category 不在 6 类内**。
