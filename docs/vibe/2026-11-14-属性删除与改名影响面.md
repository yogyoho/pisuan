# 属性删除/改名影响面（2026-11-14）

依据：`docs/vibe/2026-11-14-领域实体构建器页面设计诊断.md` §4 P1-3（删除无影响面，原文即含「属性/实体」）、§5.2「删除前弹影响面（引用该实体/属性的模板数、待审核任务数）」；上一批 [`2026-11-14-实体引用使用情况与删除影响面.md`](./2026-11-14-实体引用使用情况与删除影响面.md) 明确把「属性改名/删除前的单独影响面提示」留到本批。

## 目标

实体级删除已经会在确认前展示引用影响面；属性级操作仍是「弹窗直接删 / 直接改 key」，而属性被删除或改名后，`learned_templates.slots[].entity_ref`、待审核任务、`reports_pps.entity_key` 里的 `entity_key.prop_key` 同样会悬空。本批把同一份 usage 数据接到属性行上：删除/改名被引用的属性时先展示影响面，取消则什么都不改。

## 现状（已具备）

- `GET /entities/{identifier}/usage` 已返回逐属性四类计数（`properties[prop_key] = {templates, pending_tasks, report_pps, facts}`）与悬空引用。
- `PropertyTable` 已有「引用」列展示总次数（0 标「未使用」）。
- 属性删除是行内 `a-popconfirm`；属性改名发生在「属性定义」弹窗 `handleSaveProperty`，两处都无影响面。
- 属性编辑只改前端草稿 `draft`，真正落库在实体保存时；后端 `update_entity` 会经 `_remap_waiting_review_tasks` 清理/重建待审核任务里失效的 `entity_ref`，但**不会**改写 `learned_templates` 与 `reports_pps`。

## 范围

**做**

- `PropertyTable` 接收的 `usage` 用于属性级确认：
  - 删除属性：有引用时弹 `Modal.confirm`，列出四类条数，说明「保存实体后待审核任务引用会被清理，段落模板与报告参数中的引用会变成悬空字符串」；无引用时只提示不可恢复。取消不删。
  - 改名属性（属性键变化）：有引用时先弹同一个影响面确认，确认后才写入草稿；取消保留原属性、弹窗不关闭。
- 文案区分「删除」与「改名」两种后果，不共用一句含糊提示。
- 影响面数据缺失（新实体 / usage 未加载）时按「无引用」处理，不阻塞操作。

**不做**

- 属性级后端校验（例如拒绝删除被引用属性）：删除是设计动作，管理员的判断优先，只提示不拦截。
- 保存时自动重写 `learned_templates` / `reports_pps` 的引用（需要迁移批次，单独做）。
- 属性内联编辑、拖拽排序（§5.2 交互重设计剩余项）。

## 验收

1. 选中 `groundwater_quality`，属性 `最大值数值`（引用 233）点删除 → 弹窗列出「段落模板 211、待审核任务 22…」；取消后该行仍在。
2. 未使用属性（如 `max_value_numeric`）删除 → 只提示不可恢复，确认后行消失（仅草稿）。
3. 把 `最大值数值` 的 key 改成别的值并保存属性 → 先弹影响面；取消后弹窗仍开着、key 未变。
4. 不保存实体直接离开页面时，草稿改动按既有脏状态守卫提示，不写库。
5. 无 JS 报错；`eslint` / `prettier --check` / `vite build` 全绿。
