# 分类字典表（P1-2 / §3.2）

**日期**：2026-11-15
**诊断依据**：`docs/vibe/2026-11-14-领域实体构建器页面设计诊断.md` §3.2 问题三、§5.3.1
**前置批次**：P1-5 导入/导出对称性、P2-5/P2-6 实体接口旧账清理（已完成）

## 现状与问题

1. 分类不是独立实体，而是从实体表的 `category` 字段派生的：`get_taxonomy` 先取 `SELECT DISTINCT category`，再用写死的 `CATEGORY_DOMAIN_MAP` 补中文名。结果是：
   - 分类无法重命名、无法调整顺序、无法预先建一个空分类再往里加实体；
   - 空分类只在 `CATEGORY_DOMAIN_MAP` 里"恰好存在"时才可见，字典外的新分类只能靠先造实体才出现；
   - `repo.export_all` 又复制了一份同样的六分类映射，两处会漂移。
2. 泛化抽取 prompt 的属性截断按 `ORDER BY category, name_cn`（分类字母序）取前 60 个：
   `env_quality` / `impact_assessment` / `measures_regulation` / `natural_env` / `project_basic`
   / `sensitive_target` 里，字母序第一个是 `env_quality`，业务上最重要的 `project_basic`
   （470 个属性）排在 `natural_env` 之后，整类进不了 prompt——通用域 592 个候选属性只有 60 个
   对泛化可见（约 79% 不可见），而不可见的恰好是"谁在建/建什么"这类主力实体。

## 目标

- 分类成为可管理的字典表：`code / name_cn / description / sort_order / is_active`。
- 实体树、分类选择器、导出 taxonomy 统一从字典渲染；空分类可见可建实体；分类可新增、改名、调序、停用、删除空分类。
- 泛化 prompt 截断顺序改为"字典 `sort_order` → 实体 `name_cn`"，让业务优先级（基础工程实体在前）决定可见性。

## 范围

做：

1. 新表 `domain_entity_categories`（PK `code`），迁移 v23 建表 + 播种六条（sort_order 10/20/30/40/50/60，
   名称沿用原 `CATEGORY_DOMAIN_MAP` 的中文名与描述）。
2. `DomainEntityCategoryRepository`：list/get/create/update/delete/reorder/rank_map。
3. `DomainEntityService`：`get_taxonomy` 改为读字典（含空分类、按 sort_order 排序、字典外但有实体的分类兜底追加）；
   `export_all` 的 taxonomy 复用同一实现，删除 repo 里重复的映射；分类 CRUD + 调序服务；
   `create_entity` 与 AI 提案的 category 校验改为"必须存在于字典"；提取 prompt 的分类清单从字典生成。
4. API：`GET/POST /categories`、`PUT/DELETE /categories/{code}`、`POST /categories/reorder`。
5. 泛化 prompt：`_load_entity_schema_variables` 按字典 rank 排序后再截断 60 个。
6. 前端：树按字典顺序渲染（标题用 `name_cn`）并保留空分类的"+ 新建实体"入口；
   分类选择器显示中文名（value 仍是 code）；新增"分类管理"弹窗（新增/改名/上移下移/停用/删除空分类）；
   `computePromptCoverage` 改用字典顺序，与后端逐行一致；属性表提示文案更新。
7. 测试：字典 CRUD / 排序 / 删除保护的单测；taxonomy 顺序、分类接口、prompt 排序的集成/单元覆盖；真实浏览器 E2E。
8. 文档：本任务书、`changelog.md`、诊断文档状态注记。

不做：

- 分类 `code` 改名（它是 `entity_schema.category` 的存储值，改名需级联迁移，另列）。
- 分类颜色/图标、拖拽排序（用上移/下移按钮）、分类级权限。
- 实体表 `category` 列改外键（当前数据里可能有字典外分类，强约束会挡住导入兜底路径）。

- 验证：单测 62 passed（含新增 10 条分类单测）；集成 22 passed（含 5 条分类用例）；

## 验收标准

1. 迁移后 taxonomy 顺序为 基础工程实体→自然环境实体→环境质量与污染源实体→敏感目标与空间实体→措施与法规实体→环境影响评价实体，与字母序不同。
2. 新建空分类后立即出现在树中（0 实体），可在其中新建实体；改名与调序即时生效且刷新后保持。
3. 删除有实体的分类返回 400 并说明实体数；删除空分类成功。
4. 泛化 prompt 的前 60 个属性来自 `project_basic` 等业务优先分类（不再以 `env_quality` 开头）。
5. 前端覆盖测算与后端实际截断集合一致（逐属性对照）。
6. `pytest`、`ruff`、`eslint`、`prettier --check` 全绿；浏览器无控制台报错。
