## 1. 目标与范围

用真实用户走完全部分章管线，并与样例库**原版报告**比对生成质量。范围覆盖技能全部功能面：

| # | 功能面 | 对应管线步骤 |
|---|--------|--------------|
| F1 | 恢复/开新 + 工作区消歧 | 步骤 0 |
| F2 | 计划卡（卡A）先行 + 修订回环 | 3a 前置 |
| F3 | 门 1 表单核定 + 门 2 异常裁决 | 步骤 1/2 |
| F4 | 范例挑选卡（卡B）：编号选定 / 不用范例 | 3a-3 |
| F5 | 逐节编写（节级派发）+ 章门校验 | 3b/3c |
| F6 | 合规审查发现单 + 确认卡 + 返工回路 | 3d/3e/3f |
| F7 | 章确认 + 要点包 + 跨章衔接（后章回扣前章口径） | confirm-chapter |
| F8 | 中断恢复（关页/刷新/新会话续跑不重发已确认卡） | 恢复检测 |
| F9 | （扩展，视售后修改功能落地）已确认章的点节返工/复查 | CONFIRMED→DRAFTED |

**覆盖矩阵**：5 类 stage 各测 1 轮——`planning_eia`（规划）、`project_eia_underground`（井工）、`project_eia_openpit`（露天）、`post_eia`（后评价）、`tracking_eia`（跟踪评价）；每轮选 1 个代表性章（建议：planning/ch2、underground/ch6（沉陷）、openpit/ch5、post/ch3、tracking/ch6）。

## 2. 预先准备物（P0，测试开工前就位）

### 2.1 参照系报告（每类型 1 份，兼作测试数据源）

**选取标准**（按序）：① 目标章索引条目数最多（章节最完整）；② corpus_meta 元数据齐全（province/year/scale/standards_cited）；③ 年代较新。

| stage | 库存 | 选法 |
|-------|------|------|

| project_eia_underground | 7 | 同上 |

### 2.2 测试数据文件（从参照报告提取，落工程目录 data/）

每个 stage 一套，从参照报告提取为门 1 表单可答、ingest 可收的形态：

| 提取物 | 内容 | 来源（参照报告内） | 落位 |
|--------|------|--------------------|------|
| 核定数据项表 | 产能/矿区面积/井田划分/服务年限/矸石率等门 1 表单数据项 | 总则、规划方案章 | data/*.csv |
| 章数据表族 | 目标章写作所需表（如沉陷预测参数、敏感目标清单、功能区划表） | 对应专项章 | data/*.csv |
| 敏感目标清单 | 生态保护区/水源地/村庄等（含与门 1 口径的自洽性） | 环境现状/敏感目标章 | data/*.csv |

提取纪律（承 live 测试教训）：**数据必须自洽**——门 1 表单、数据表、敏感目标三者口径互洽，矛盾数据会被管线拦下（属正常防护，但测试数据不应主动制造）。

## 3. 测试流程（每被试 × 每 stage 一轮）

1. 准备：发数据文件、发 S0 → 走 S1–S5 全流程（观察者只记录不干预）
2. F8 恢复：S5 确认后刷新页面 + 新会话「继续」各一次
3. F7 衔接：S7 写次章前 3 节，检查是否回扣要点包
4. 交付：收集成稿、发现单、要点包、全程对话记录
5. **过程监控（Langfuse）**：测试期间通过 Langfuse 服务跟踪写作线程——每章 run 的 trace（时长、工具调用序列、token 用量）作为客观过程数据，与主观打分互证；trace 异常（超时/工具失败重试）同步记入缺陷清单

被试配置：环评专业人员 3–5 名；每人至少跑 2 个不同 stage（体验差异）；账号用普通用户（顺带验证非 admin 权限路径）。

## 4. 评估维度与评分表

### 4.1 生成质量 vs 参照系（脚本自动 + 人工）

| 指标 | 方法 | 及格线 |
|------|------|--------|
| 结构覆盖 | 成稿章标题集 vs stage 必备集（章门已断言，此处人工复核合理性） | 无缺无自创 |
| 深度 | 有效字符数 vs depth_targets 章地板 + 参照系同章字符数对照 | ≥地板；达参照系 50%–150% 区间 |
| 数据密度/表密度/文表联动 | 章门指标 vs 参照系同章实测三指标 | 全部达门且不显著低于参照系 |
| 数值保真 | 抽 10 处核定值引用比对提取物 | 0 错配 |

### 4.2 交互体验（被试打分，5 分制）

对**卡 A**逐项打分（对应你的要求）：
- ① 是否讲清了**本章特点/定位**（这章干什么、与前后章关系）
- ② 是否讲清了**需要提供哪些数据文件/数据表/数据项**
- ③ 是否给出了**本章编写注意事项**
- ④ 是否体现了**写作思路**（编写要点）
- ⑤ 卡面可读性（零内部词/零英文夹杂）；⑥ 每个卡点「下一步该做什么」是否自明；⑦ 打断/恢复体验

及格线：①–④ 均分 ≥4.0；⑤ 禁用词/内部词泄漏 = 0（含降档、BLOCKED、裁决、协商单等 SKILL.md 禁用词清单全量，bug-4155 整改验证点）。

### 4.3 行文风格（盲评）

- 将成稿与参照系同章**各自删去标题标识**后并列，环评评审者盲评：工程师复合句式、数据从句串联、文表引用与解读、AI 腔（总体而言/值得注意/至关重要等）检出数
- 评分：成稿 ≥ 参照系 − 0.5（5 分制）为过；AI 腔每千字 ≤1 处

### 4.4 范例卡脱敏参与（卡 B 专项）

- 候选卡展示的候选条目**不含**报告名/report_id/来源路径（脱敏验收）
- 被试能否仅凭「章节完整度/篇幅/结构特点」作出有依据的选择；记录选择理由
- 选定后成稿与所选范例的结构相似度抽样对比（验证范例确实被参照）

## 5. 通过标准（全量满足才算过）

1. 5 个 stage 全走通，0 例 BLOCKED（或 BLOCKED 均走协商单有出路）
2. 4.1 四项指标全达标；4.2 ①–④ ≥4.0、内部词 0 泄漏；4.3 盲评达标；4.4 脱敏零泄漏
3. F8 恢复两场景均不重发已确认卡
4. 缺陷全部入 buglog 并分级；P0 级清零后出具测试报告
