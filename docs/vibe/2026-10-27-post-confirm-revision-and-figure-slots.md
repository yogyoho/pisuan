# 交付后章节修改 + 插图占位 · 需求文档

> 日期：2026-10-27　状态：**已立项**（用户拍板）
> 背景：第2章 CONFIRMED 后，客户存在反复修改诉求（润色/改数据/逻辑重写/插图占位/复查/特殊修改）。现状机制：状态机 `CONFIRMED → DRAFTED` 唯一出口（progress.py:78）+ 3f 返工回路 + coal-eia-reviewer 独立可复用。

## 目标

已确认章节在不绕过质检的前提下可反复修改；正文支持插图占位（不插真图，留位由用户自行插图）。

## 需求项

### R1 已确认章点节返工（润色 / 小节级修改）
用户在对话点名「润色第2章 2.3 节」→ 智能体受理：受影响节 `mark --sections … DRAFTED`（原稿+意见注入）→ 章门+审查重跑 → 确认卡重发 → `confirm-chapter`（highlights 幂等并入要点包）。
**改动**：SKILL.md 新增「已确认章修改」用户路径小节（`progress.py next` 自动跳过 CONFIRMED 章，必须显式受理，禁静默拒绝）。
**验收**：live 实测——已确认章点名润色一节，全链路（重派→门 PASS→发现单→确认卡）走通；确认后其他章要点包回扣新口径。

### R2 数据修改级联
核定值修改 → ingest/formula_runner 重跑 → **所有引用该值的章节**（含其他已确认章）受影响节重派 → 重门。
**改动**：SKILL.md 数据修改路径说明（复用 BLOCKED 补数据同款链路）；跨章级联时如实告知用户受影响章清单再动手。
**验收**：改一个全局核定值（如矿区面积），受影响各章均重门并更新占位值，无旧值残留（残留扫描门兜底）。

### R3 轻量复查（不改稿只出发现单）
直调 `coal-eia-reviewer`（技能本身「只审不改、独立可用」，无需动 progress 状态机），产出新的发现单文件，不改变章节状态。
**改动**：SKILL.md 补一句「已确认章复查＝直接调 reviewer，不改状态」。
**验收**：对已确认章发起复查，得到发现单，progress.json 状态不变，成稿零改动。

### R4 返工轮次放宽
每章返工 ≤2 → **≤5**（私有化部署不计 LLM 成本；保留上限仅防对话失控）。writer/chapter-writer SKILL.md 同步。
**验收**：第 3~5 轮返工不再触发协商出口。

### R5 插图占位（`{{FIG:…}}` 占位族）
- 节写手在适图位置落 `{{FIG:图名}}` 占位（如 `{{FIG:矿区井田划分图}}`），图名用业务语；
- build_output 占位符门：FIG 列入**合法占位符族**（现行门把未解占位符判 FAIL，须放行 FIG 并校验图名非空）；
- 确认卡附**插图清单**：图名 / 建议插图内容（一句话）/ 所在节；
- 成稿交付时占位原样保留（用户后续自行插图），发现单可提示「插图 N 处待补」。
**改动**：占位符门逻辑、3b 派发契约（插图纪律一句）、确认卡版式（清单块）。
**验收**：成稿含 ≥1 个 FIG 占位且门 PASS；确认卡清单与正文占位一一对应；SLOT/TABLE 既有校验不回归。

### R6 用户沟通语体硬约束（已完成部分）
SKILL.md 沟通规范已落**禁用词清单**（降档/BLOCKED/裁决/协商单/回环/派发/额度/折算/地板/冻结），含替换说法；writer 4.5 降档选项卡面文案同步改写。
**验收**：归入用户测试方案 4.2⑤（内部词/禁用词零泄漏）。

## 明确不做

- 不做真插图/图片库/导出链路（二期另立）；
- 不做「绕过门直接改字」的快改通道（质检旁路违反复门红线）。
