# 章节编写交互卡点设计（计划卡 + 范例挑选卡 + 篇幅选择化）

- 日期：2026-10-26
- 状态：已实施（2026-10-26；双包各 207 passed，栈四副本落栈哈希核对；真实对话冒烟待用户侧验证）
- 关联：bug-4147（样例片段包）、bug-4145（问什么由门1裁决）、bug-4142（用户沟通规范）、bug-4148（深度折算）、bug-4146（门凭据）

## 1. 背景与痛点

现状分章链路（chapter-writer）中，用户发起「写第 N 章」后只能看到两端：开头被要资料（门1 缺项卡）、结尾收确认卡。中间的样例选取（3a-3 静默取主导报告切片）与节级写作（3b 静默派发）全程黑盒。用户需求原话归纳：

> 用户提出编写环评报告的章节，agent 需要告知用户该章节编写思路、编写要点、编写过程的细节，用户确认（有补充意见则完善后再确认），然后管线执行；执行过程中从 KB 取报告章节段落模板时，也要呈现给用户确认，用户确认选择后再用该模板写作。

即新增两个人工确认点：**卡A 计划卡**（管线执行前）、**卡B 范例挑选卡**（写作前）。

## 2. 设计定案（用户已逐项确认）

| 决策点 | 定案 | 用户选择 |
|---|---|---|
| 范例选择粒度 | 多候选挑一：top-3 候选摘要卡，用户回复编号选定；「不用范例」为合法出口（用户显式豁免，如实注明影响；红线 P10 禁的是 agent 自主跳过） | B |
| 计划卡密度 | 摘要卡：一屏读完（定位一段话 + 要点 3~5 条 + 需准备数据 + 过程预告）；逐节明细不做（信息到范例卡/交付时才是实的） | A |
| 确认持久化 | 落盘 state 工件（plan/fragment_choice），**状态机 TRANSITIONS 不动**——凭据语义留给质量门（bug-4146 一致性），计划/片段属写作输入协商 | 决定（未否决） |
| 深度基准 | 样例库中位折算只产生「详实版推荐篇幅」数字，不再无条件硬门槛——硬不硬由用户在计划卡选 | 决定（见下） |
| 篇幅强制？ | **不强制，用户选择**：计划卡新增「篇幅规模」①详实版（推荐 N 字）②精简版（不启用篇幅规则）③自定义字数；①/③ 未达时业务化协商（扩写 or 按现稿收尾=降档留痕），② 如实注明 | 用户修正 |
| 术语转译 | 「深度地板/折算/深度目标」禁出现在用户可见文字，统一「篇幅规模」；术语映射表补行 | 用户修正 |

## 3. 目标链路

```
用户:"写第2章"
 → 步骤0 工作区消歧（既有，不动）
 → 【卡A 计划卡·摘要式】
     本章定位（stage 大纲一句话）
     编写要点 3~5 条（节清单 + 样例共性提炼，业务语体）
     需要您准备的数据（中文名，与门1 --chapters 裁剪口径一致）
     篇幅规模：①详实版(约N字) ②精简版 ③自定义 —— 缺省①
     过程预告（确认后核对资料→资料齐后挑范例→动笔→自检→请您审查）
 → 用户「确认」→ progress.py plan-confirm 落盘 → 门1 缺项卡 → 门2 增量冻结（既有）
   用户提补充意见 → 合入重发修订版卡（变化处标注）→ 再确认（回环不设上限，agent 应收敛）
 → 【卡B 范例挑选卡】3 份候选:
     每份 = 来源报告 · 覆盖节数 · 约字数 · 开头摘录两行
 → 用户回复编号 → sample_fragments.py --report-id 取件 → progress.py fragment-choice 落盘
   用户回「不用范例」→ fragment-choice --none → 派发契约注明「用户选择不参照范例」
 → 3b 写作（契约注入：选定范例包路径 + 计划要点 + 用户补充意见 + 篇幅选择）
 → 单章门 gate → 审查（reviewer 收到计划卡补充意见，核对兑现；规程层非硬门）
   → 确认卡 → CONFIRMED（既有，全部不动）
```

计划卡时机在**门1 之前**：「需要您准备的数据」预告与门1 缺项卡互补（预告讲数据族，门1 卡列具体缺项）。

## 4. 篇幅规模语义表

| 用户选择 | plan 工件 | 单章门行为 |
|---|---|---|
| ① 详实版 | `depth: full` | 篇幅目标启用（推荐字数=样例库中位折算，展示取整到千字）；未达时**不静默拦死**：如实告知当前字数与目标，问「继续扩写 or 按现稿收尾（注明篇幅差距）」；收尾=approve-downgrade 降档留痕放行（既有语义，业务化包装） |
| ② 精简版 | `depth: compact` | 篇幅规则不启用；门输出注明「用户选择精简篇幅」 |
| ③ 自定义 | `depth: custom, target: N` | 以 N 为目标，其余同① |
| 无 plan 工件（存量工程 / writer 全书模式） | — | 维持现状强制语义，**零回归** |

## 5. 脚本与工件改动

- `sample_fragments.py`（writer 真源，sync 到 chapter-writer）：
  - 新子命令 `candidates --stage S --chapter chN [--top 3] --out <json>`：top-N 确定性排序（索引条目数降序、report_id 字典序），输出候选摘要（report_id、节覆盖数、字符数、溯源标记）；rc 0/2/1 同现有
  - 主命令加 `--report-id`：按用户选择取件；缺省仍主导报告（自动挑选降级为缺省值）
- `progress.py` 新增两个子命令（不新增状态）：
  - `plan-confirm <chN> --summary-file <卡面md> --notes "<补充意见>" [--depth full|compact|custom] [--target N]` → 写 `state/plan_<ch>.json`（卡面内容+意见+选择+时间戳）；幂等（重确认覆盖）
  - `fragment-choice <chN> --report-id <id> | --none` → 写 `state/fragment_choice_<ch>.json`
- `next` 联动：COLLECTING 分支内按工件存在性修饰提示（无 plan → 先发计划卡；有 plan 无 choice → 先发范例挑选卡）；不改 TRANSITIONS
- SKILL.md（chapter-writer）：步骤重排（计划卡插入开题路由后、门1 前；3a-3 改写为候选卡流程）、红线 P13（无 plan 不开工、无 choice 不派发）、篇幅选择分支规程、术语映射补「篇幅规模」行、审查联动一句
- 范围：**只动 chapter-writer 链路**；writer 全书模式暂不同步

## 6. 验收标准（用户视角）

1. 发起编写后、要资料前，先收到一屏计划卡（定位/要点/需准备数据/篇幅选择/过程预告）
2. 回复补充意见后收到修订版计划卡，要点体现补充内容
3. 资料齐后收到 3 份范例候选卡；回复编号即选定开写；回复「不用范例」也能继续
4. 选「精简版」时写作不被篇幅拦；选「详实版」未达时收到「扩写 or 收尾」的询问而非静默失败
5. 全程业务语体（无命令/路径/状态枚举/「深度地板」类术语）
6. 新会话恢复不重发已确认的卡（工件存在即跳过）
