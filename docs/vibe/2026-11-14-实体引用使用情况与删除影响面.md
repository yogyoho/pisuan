# 实体引用使用情况与删除影响面（2026-11-14）

依据：`docs/vibe/2026-11-14-领域实体构建器页面设计诊断.md` §4 P1-3（删除无影响面）、§4 P2-3（属性是否被使用无提示）、§5.3.2（使用情况面板）。

## 目标

让「实体/属性到底有没有被消费」在构建器页面上可见，并把删除从「一键不可恢复」变成「先看影响面再确认」。

## 现状（实测 2026-11-14 通用域）

| 引用来源 | 行数 | 说明 |
|---|---|---|
| `domain_factory_learned_templates.slots[].entity_ref` | 211 模板 | 唯一有实内容的持久引用；当前全部指向 `groundwater_quality.最大值数值` |
| `domain_factory_tasks.source_paragraphs[].template.slots[].entity_ref` | 4 个 WAITING_REVIEW 任务 | 引用最丰富，含 `entity_key.prop_key` 与 `entity_key.中文名` 两种历史格式 |

| `domain_factory_regional_facts.entity_key` | 0 行 | 区域事实（B 类确认实体） |

`domain_factory_outlines.entity_bindings` 当前全空，本轮不纳入扫描。

## 范围

**做**

- 后端 `GET /api/domain-entity-builder/entities/{identifier}/usage`：
  - 按实体统计四类来源的引用条数（模板数 / 待审核任务数 / 报告参数行数 / 区域事实行数）；
  - 逐属性统计引用数（属性 key 与历史中文名后缀都归一到 key）；
  - 输出「未使用属性」与「悬空引用」（entity 命中但属性已不存在）；
  - 返回最近引用的模板/任务明细（模板按 updated_at 取前 20）。
- 前端右栏「使用情况」卡片：四类计数、未使用属性清单、悬空引用清单、最近引用明细。
- 属性表新增「引用」列：每属性被引用次数，0 标「未使用」。
- 删除确认改为先取影响面：有引用时列出各类条数并提示引用会悬空；无引用时提示不可恢复。取影响面失败则不删除。

**不做**

- 软删除/恢复（需要表结构与回收站 UI，单独一批）。
- `outlines.entity_bindings` 扫描（当前无数据，接入时再扩）。
- 属性改名/删除前的单独影响面提示（删除实体已覆盖，属性级留待下一批）。

## 验收

1. 选中被 211 条模板引用的 `groundwater_quality`，使用情况显示「段落模板 211」，属性 `最大值数值` 引用列为 211。
2. 选中被待审核任务引用的实体（如 `noise_equipment`），计数与任务明细一致；含中文名后缀的引用计入对应属性。
3. 删除任一被引用实体，弹窗列出影响面清单；点取消后实体仍在。无引用实体只提示不可恢复。
4. `pytest` 新增用例通过；前端 lint/build 无新增错误。

## 口径约定

- `entity_ref` 以第一个点号切分：前缀是 entity_key，后缀是属性 key（历史中文名后缀经 `name_cn → key` 归一）；无后缀的引用按实体级引用计数。
- 报告参数 `entity_key` 同时接受裸键与 `project.xxx` 点号形态，前缀命中即计入。
- 同一模板内同一属性出现多次按多次计（引用次数），模板数按去重模板计数。
