# 环评写作技能全面测试复盘 → 知识工厂重构方向

- 日期：2026-10-08
- 性质：需求方向文档（非本次实施——「现有知识工厂的功能先别动」约束仍有效）
- 证据基线：coal-eia-writer 技能 bug-393/394/395 三轮修复 + ch6_S05 单节页面验证 + test2 交付稿一致性门全景（pass 10 / warn 12 / manual 15 / skip 8 / fail 0）

## 一、目标

把技能全面测试暴露的薄弱点，转化为知识工厂对环评样例报告加工的产出物清单与重构方向，回答一个问题：**样例报告加工应该产出什么，才能治住写手侧、数据侧、门侧的实测缺陷。**

## 二、薄弱点盘点（全部有实证）

### 写作侧

## 三、样例加工产物 → 弱点映射

|---|---|---|

| 范文指纹库 | G2 | SL3 风格漂移抽检的学习样本 |

## 四、重构方向（按杠杆率排序）

1. **范式库从「角色」细化到「节型 × 形态」**：语料来自样例报告逐节抽取，重点补「表格引导句」「图表交叉引用」「结论收束」三个高频形态。给正样本永远比给禁令可靠——这是治写手随机性的根本手段。
2. **逐节数值-口径清单（expected_quantities）进节契约**：让「哪些数字必须精确引用」成为一等公民；缺数清单写作前与 data/ 对账，缺项提前暴露。
3. **表格 schema 学习 + 离线 schema linter**：样例表格 → stage forms 的生成/校验通道，把三轮人肉修 schema 变成离线自动项。
4. **样例范围扩到规划/后评价/跟踪阶段**：SL3 断层说明样例库只有项目环评，而五个 stage 里四个缺样例——样例不全，前三条对多数阶段无效。**建议列为前置项。**
5. **合约机器态载荷供给**：一致性注册表 T4 接知识工厂抽取的结构化实体，manual 15 条才可能自动化。

一句话方向：知识工厂对样例报告的加工产出，从「给写手看的参考资料」（writing_example/hints）升级为「给管线消费的结构证据」——逐节句式范式、数值口径清单、表格 schema、合约载荷。

## 五、验收标准（重构落地时的 checklist）

- [ ] 范式库：77 节每节有专属范式或显式归并说明；「表格引导句」「交叉引用」「结论收束」三形态有样例统计支撑（形态占比+例句）
- [ ] expected_quantities：抽验证节（≥3 节）的清单与样例报告实引数值对得上（人工核对通过）；XS2 warn 在清单覆盖节内降为可校验断言
- [ ] schema linter：对 5 个 stage 现有 forms 离线跑通，输出 label 缺失/竖线/枚举非 canon/单位缺失四类报告；bug-366/393/394 三轮人修项可被 linter 重发现
- [ ] 样例扩阶段：规划环评至少 1 份样例入库加工，SL3 warn 消除（指纹抽检可跑）
- [ ] 合约载荷：至少 1 条 manual 合约（建议 XS6 口径标签类）拿到机器态载荷转自动断言
- [ ] 全程不回归：技能侧既有门（形状/深度/槽位/残留/摆位/一致性 fail=0）保持绿；pisuan core 不动或最小化
