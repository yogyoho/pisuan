## 3. 设计

### 3.1 分类器收敛（`classify_paragraphs`，service:1634）

- 路由 1-5（heading/table/figure/formula/legal_reference）**原样保留**。
- 原路由 6（parameter 判定）+ 路由 7（narrative）合并为 **prose 回退**：`classify_type="prose"`。
- 参数信号降级为标签（02 文档 Q1"type 降级为标签"）：`_UNIT_RE/_PARAM_VERBS/_SLOT_PATTERNS` 保留，prose 段仍计算并写入 `classify_tags`（measurable/reusable/descriptive——前端 :1105 在展示）。
- `_NARRATIVE_SUBTYPE_KEYWORDS` 与 `_match_narrative_subtype` 删除（classify_tags 消费方仅前端展示，叙述子型无消费，死亡无副作用）。
- `classify_type` 已标记段落跳过重分类的既有语义保留。

### 3.2 P1-0 双产物统一泛化

- **todo 过滤**（:822）：`classify_type == "parameter"` → `_PROSE_TYPES = ("prose", "parameter", "narrative")` 三值（新任务 prose；旧任务续跑双读）。断点续跑「无模板或 fallback 模板才重做」条件不变。
- **提示词 v2**（`_PROMPT_DEFAULTS["template"]`）：现有模板已含 `narrative_placeholders`（结构标记）与 `condition`（判断逻辑），**增量 = `summary` + `key_points` 两字段**进入输出 JSON 结构说明；同步前端 PromptConfigView.vue 的 defaultPrompts（文件头注明与 `_PROMPT_DEFAULTS` 保持同步的既有约定）。
- **回写**（:883）：`para["template"]` 增加 `summary`/`key_points` 透传（`_normalize_template_response` 补 `setdefault`）；quality_score 语义不变。
- **覆盖率分母修订**（:922）：`classify_type not in (None, "heading", "narrative")` → 分母 = prose 三值段落（新产物定义下散文段全部可泛化）；注释记录口径变更日期与依据。
- **续跑边界**：legacy 任务中叙述段带旧路径 template（无 fallback 标记）→ 续跑永久跳过，接受（旧任务可整卷重跑获得双产物）。

### 3.3 P1-1a 结构化输出 + 闭式类型词表

- **词表选型**：现有 4 类 `{parameter, enum, descriptive, reference}`——后端 `_normalize_template_response._valid_types` 与前端 `SLOT_TYPE_MAP` 已同源，legacy 数据同词表。**不采用** 02 文档草案的数值/文本/枚举/引用/日期五类（级联改名、零行为收益）。单一词表常量提升为类常量，prompt 文本与 normalizer 同源引用。
- **prompt 补词表**：现模板 slot 示例只写 `"type": "类型"`（不给枚举 = bug-337 根因：99.7% 强转），补四类型枚举与各自含义。
- **结构化通道**（service 层实现，`chat.py` 零 diff）：经 `select_model()` 返回的 adapter 暴露的 langchain 模型（`adapter.model`）做 JSON 约束绑定（`bind(response_format=...)` 或 `with_structured_output`，按 provider 支持度）；**能力探测每模型实例一次**并缓存——不支持 → INFO 日志一次，走既有 prompt 通道。这是 provider 能力协商（显式日志+计数），不是错误掩盖。
- **解析次序**：结构化返回 → 既有 regex JSON 提取（降级通道）→ `_generalize_fallback`（metadata.fallback=True）。重试/熔断/StepOutcome 语义不动；`step_ledger` 增加分通道计数（structured/prompt），随台账落库上浮。

## 4. 数据流与不变量

- 零 schema 变更；prose.template 形状 = `{generalized, original, slots, metadata, quality_score, summary?, key_points?}`（后两字段新增可选）。
- 每散文段**恰一次**泛化调用——结构化与降级是同一调用的两种解析通道，不构成额外调用。
- 熔断/退避/断点续跑/StepOutcome 台账语义不动；`ai_confidence` 口径不变。
- 旧任务双读：所有 parameter/narrative 判断点 → 三值元组；**旧值永不改写**（不做数据迁移）。
- `chat.py`（上游共享）/`unified.py`/`ocr_service` 零 diff。

## 7. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 散文类命名 `prose` | 与"结构类+散文回退"表述一致；parameter/narrative 保留为 legacy 读兼容值 |
| D2 | 词表用现有 4 类，不用 02 草案五类 | 后端/前端/存量数据已同源 4 类；改名零收益纯风险 |
| D3 | 结构化输出在 service 层实现 | chat.py 上游共享（main 有提交），约束"最大不动"；adapter.model 已暴露 langchain 模型 |
| D4 | 降级通道保留非防御回退 | provider 能力差异的显式协商：探测缓存 + INFO + 分通道计数，故障可见 |
| D5 | text_pattern 幽灵字段顺带修复 | 门在本批触点内；保留即知情的恒假校验，buglog 立档 |
| D6 | descriptive 标签语义放宽为"数值且无单位无槽名"（2026-10-06 质量审查裁决） | 原"参数分支入口要求 verb\|unit\|slot 其一"中的 verb 属路由信号，随双轨废弃一并退役；classify_tags 无分支型消费方（前端仅透传展示），放宽无断裂；补测钉住行为 |
| D7 | validator generalized 门收敛 prose+parameter 双值，legacy narrative 豁免（2026-10-06 控制器裁决） | narrative 仅存 legacy 值（旧摘要形态模板无 generalized，bug-336 产物），纳入会令 legacy 任务新增性提交失败，违反 DoD#4 消费面双读不回归；新任务分类器不再产出 narrative，豁免无漏报面 |
